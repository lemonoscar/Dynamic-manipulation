# 第三次物理诊断 DWA 失败审核

本次没有到达 PICK。8 次模型调用均为 CONTINUE / NAV_TO_SOURCE；161 个物理 tick 后，以 `dwa_zero_control_before_reach` 停止。

直接日志显示，3.20 s 第八个 query 的执行目标 B 为 `[-0.9152450562, 6.2248662949, 1.4449595626]`，snap 为 0.1036367492 m。当前距离 B 为 0.1187292866 m，朝向误差 0.3750588298 rad，因此执行原地转向 `[0,0,-0.35]`。其后实测状态为 3.22 s；由该状态计算距离增至 0.1206814660 m，朝向误差降至 0.3675506888 rad。机器人仅越过 0.12 m 分支边界 0.681 mm，即切回 DWA。

**已排除 DWA/上层距离门不一致。** 冻结代码在构造时调用 `bind_reach_config`，将 DWA 原始配置替换为 0.12 m，与上层一致；不能用源 DWA 默认 0.35 m 解释本次失败。

**原始零命令与 guard 清零仍无法区分。** 原始 guard 会将 `0 < abs(vx) < 0.16` 清零，并保留非零 wz。失败分支没有记录 raw DWA 命令或 `adapter.last_trace`；runner 又在记录拒绝控制前抛错。因此直接证据仅支持“切回 DWA 后 guarded command 为零”，不支持断言原始 DWA 已经到达、碰撞阻塞、或一定是 guard 清零。最后失败 tick 未重跑模型或物理，也未猜测内部候选评分。

最小后续修复是先完整保存失败 tick 的 DWA debug、raw/guarded command，再为末段平移/转向使用一致的状态保持与滞回，并明确定义制动零命令；保留原 0.12 m / 0.14 rad 验收门。先做 CPU 边界测试，后续物理需要独立预算。本审核未修改代码、未使用 GPU。
